# Digital Robotics Platform v2 — Low-Level Design

Version 0.1 (draft for review) · 2026-11-06 · Owner: T.N · Implements [SRS-v2](../SRS-v2.md) v0.2 and [HLD-v2](../HLD-v2.md) v0.2

The LLD is the build specification. It gives, for each module:
- the tables (columns, types, indexes);
- enums, models, services and their algorithms;
- policies, routes, Form Requests, the props sent to Vue, and the pages;
- notifications, jobs and tests.

A developer should be able to implement a module from its file without guessing.

## 1. Naming and code conventions

| Item | Convention | Example |
| --- | --- | --- |
| Module root | `app/Domain/<Module>/` | `app/Domain/Events/` |
| Namespaces | `App\Domain\<Module>\{Models,Actions,Services,Policies,Enums,Data,Events,Listeners,Notifications,Jobs,Rules}` | `App\Domain\Events\Actions\ApproveRegistration` |
| Controllers | `App\Http\Controllers\{Public,Console,Workspace,Auth,Account}\<Name>Controller` | `Console\EventRegistrationController` |
| Form Requests | `App\Http\Requests\<Area>\<Verb><Noun>Request` | `Workspace\StoreRobotRequest` |
| Resources | `App\Http\Resources\<Noun>Resource` (+ `<Noun>ListResource` for tables) | `RobotResource` |
| Actions | One public `handle(...)` method, verb-noun, `final` | `CreateRobot::handle(Team, RobotData): Robot` |
| Services | Several related operations on one aggregate | `LedgerService::post(...)` |
| Data objects | `readonly` classes in `Data/`, built from validated input | `RobotData::fromRequest($request)` |
| Enums | String-backed, TitleCase cases, `label()` translated | `RegistrationStatus::Waitlisted` |
| Tables | Plural snake case; pivots in alphabetical singular order | `event_registrations`, `registration_robot` |
| Routes | Names `public.*`, `console.*`, `workspace.*`, `account.*`, `auth.*` | `workspace.robots.store` |
| Vue pages | `resources/js/pages/<area>/<Noun>/<View>.vue` | `pages/workspace/Robots/Edit.vue` |
| Permissions | `<area>.<action>` lowercase | `events.approve` |
| Pennant features | `<noun>.<verb>` matching SRS B.2, one class each | `Features\RobotsCreate` with `$name = 'robots.create'` |
| Translations | `lang/{en,ar}/<module>.php`, keys `<module>.<screen>.<key>` | `events.registration.waitlisted` |

PHP rules (Boost and Pint) apply to every file:
- constructor promotion;
- explicit return types;
- curly braces always;
- PHPDoc array shapes on array parameters;
- no inline comments unless the logic is complex.

## 2. Shared column patterns

| Pattern | Columns | Notes |
| --- | --- | --- |
| Primary key | `id bigint unsigned auto_increment` | Every table |
| Timestamps | `created_at`, `updated_at timestamp null` | UTC |
| Soft delete | `deleted_at timestamp null` + index | User-facing records only (listed per table) |
| Slug | `slug varchar(120) unique` (or unique per parent) | Generated by `App\Support\Slugger::unique(Model, string)` |
| Bilingual | `<field>_en`, `<field>_ar` (same type; `_ar` nullable) | `HasLocalizedFields` trait: `localized('title')` returns the AR value when the locale is `ar` and it is filled, otherwise EN |
| Money | `<field>_minor bigint` + `currency char(3) default 'LYD'` (+ `rate_to_lyd decimal(18,8)` on finance rows) | Cast with `App\Support\Money\MoneyCast` to `Brick\Money\Money` |
| Status | `status varchar(24)` + index | Cast to an enum; changed only through Actions |
| Actor | `created_by`, `approved_by`, `reviewed_by` `bigint unsigned null` FK users `nullOnDelete` | Set inside Actions from `auth()->user()` (the impersonator is recorded in activity, see 01) |
| Ordering | `position smallint unsigned default 0` | Drag-ordered lists |

### 2.1 Shared support classes (`app/Support`)

| Class | Purpose |
| --- | --- |
| `Slugger` | `unique(class-string $model, string $source, array $scope = []): string` produces `name`, then `name-2`, and so on, with the `Str::slug` Arabic fallback `item-{random6}` |
| `HasLocalizedFields` (trait) | `localized(string $field): ?string`; `scopeSearchLocalized($q, string $field, string $term)` searches both columns with `LiteralLike` |
| `LiteralLike` | Ported from v1: escapes `%`, `_` and `\` for LIKE searches |
| `Money\MoneyCast` | Eloquent cast `Money ⇄ (amount_minor, currency)`; constructor args are the minor column and currency column names |
| `Money\MoneyFormatter` | `format(Money $m): string` gives `1,250.500 LYD` with Western digits (D-11) |
| `Dates\LocalDate` | `format(CarbonInterface $d, string $pattern = 'd MMM y'): string` with ICU `@numbers=latn`, so Arabic month names appear with Western digits |
| `Concerns\BelongsToTeam` (trait) | `team()` relation; `scopeForTeam(Builder, Team)`; boot guard that refuses to save without `team_id` |
| `Concerns\HasStatusTransitions` (trait) | `transitionTo(BackedEnum $to): void` checks `$to` against `static::allowedTransitions()` and throws `InvalidTransition` |

### 2.2 Standard exceptions

| Exception | HTTP | Use |
| --- | --- | --- |
| `App\Exceptions\DomainRuleViolation` (with `violations: list<string>`) | 422, shown as form errors | Business rule failed (entry rules, limits) |
| `InvalidTransition` | 409, shown as a toast | Status change not allowed from the current state |
| `FeatureUnavailable` | 403 | A team feature is off |
| `WorkspaceMismatch` | 404 | A record does not belong to the URL's workspace |

The exception handler maps these to Inertia responses: redirect back with errors or a flash for form requests, or the `Error.vue` page for full-page requests.

## 3. Global enums

| Enum | Cases |
| --- | --- |
| `Locale` | `En = 'en'`, `Ar = 'ar'` with `dir(): 'ltr' or 'rtl'` |
| `WorkspaceType` | `Team`, `Department` |
| `Currency` | `LYD`, `USD`, `EUR` (SRS C-12; extend here) |

Module enums are defined in their own files.

## 4. How each module file is laid out
1. Scope and SRS IDs.
2. Tables (columns, types, nullability, defaults, indexes, FKs).
3. Enums and state transitions.
4. Models (relations, casts, scopes).
5. Actions and services (signatures and algorithms).
6. Policies (ability → rule).
7. Routes (method, URI, name, controller, middleware, ability).
8. Form Requests (rules).
9. Props and resources sent to Vue; pages.
10. Events, notifications and jobs.
11. Tests (named test cases).
